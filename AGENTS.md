# AGENTS.md

Локальная версия сайта кейтеринг-сервиса Rider Kitchen (оригинал:
riderkitchen.ru). Полный план работ и статус — в
[`docs/PLAN.md`](docs/PLAN.md), баги оригинала — в
[`docs/BUGS.md`](docs/BUGS.md). Прочти их перед крупными изменениями —
тут только быстрые ориентиры и жёсткие правила.

## Стек и команды

React + TypeScript + Vite. Линтер — oxlint.

```bash
npm run dev        # локальный сервер с hot-reload
npm run build      # прод-сборка в dist/ (проверяет типы + собирает)
npm run lint       # oxlint
npm run test:unit  # юнит-тесты, Vitest (tests/unit/)
npm run test:e2e   # e2e, Playwright (tests/, 4 вьюпорта)
npm run test       # оба набора: test:unit + test:e2e
```

Прогоняй `npm run build` и `npm run lint` перед тем, как считать
задачу готовой — сборка проверяет типы всего кода, включая тесты
(`tsconfig.json`: references на e2e + unit).

CI: [`.github/workflows/ci.yml`](.github/workflows/ci.yml) — на push в
`main` и PR те же проверки гоняются в 4 независимых джобах (lint /
unit / e2e / build, параллельно). e2e-джоба ставит chromium через
`npx playwright install --with-deps chromium`; отчёт Playwright
сохраняется артефактом при провале.

## Жёсткие правила

- **Без стейт-менеджеров, роутеров и подобных библиотек**, пока не
  появится реальная необходимость — сайт в основном контентный.
  Исключение по той же логике: `jspdf` + `html2canvas-pro` для
  экспорта заказа в PDF (тянутся динамическим `import()`, в отдельных
  чанках — стартовую загрузку не тормозят).
- **Контент отдельно от компонентов**: тексты/цены/меню — в
  `src/content/`, а не зашиты в JSX. Проще редактировать и
  презентовать правки владельцу.
- **Строгая типизация**: типы для меню/блюд/цен в
  `src/content/types.ts` — опечатка в поле должна подсвечиваться
  сразу.
- Новый компонент — только если кусок используется 2+ раза или это
  явная смысловая единица (карточка блюда, хедер). Не выносить в
  компонент то, что используется один раз.
- Фото в `src/assets/` — только WebP (не PNG/JPEG): конвертация через
  `cwebp -q 82 -m 6`, ресайз короткой стороны до 900px там, где
  оригинал крупнее (см. историю коммитов/чат для точной команды).
  Оригинал сайта был на PNG под сотню МБ — сюда это не тащим.

## Структура

```
src/
  components/   # переиспользуемые UI-блоки
  content/      # тексты, меню, цены, типы — отдельно от разметки
  assets/       # изображения (только .webp)
  styles/       # партиалы App.css (01-header … 09-pdf); App.css — агрегатор @import, порядок каскада критичен
  hooks/        # хуки (useCart)
  lib/          # чистые функции: catalog, order, format, exportPdf
tests/
  unit/         # юнит-тесты, Vitest
  *.spec.ts     # e2e, Playwright (4 вьюпорта)
```

## Известные особенности / открытые вопросы

- `src/assets/hero.webp` — логотип-плакат ("RIDER KITCHEN — FEED
  YOUR TEAM"), не фотография. Показывается отдельным элементом в
  правой панели Hero на натуральной пропорции 1680×994 (без
  `object-fit: cover`, который обрезал плакат — баг из docs/PLAN.md
  закрыт). Тексты Hero — в `src/content/hero.ts`.
- Цветовая палитра: `#262626` (тёмный) / `#FFE8DB` (светлый
  персиковый), акцент — травяной зелёный `#3a7d44` (в тёмной теме —
  мятный `#8ccfa0`) — CSS-переменные в `src/index.css`. Тема по
  умолчанию — светлая; тёмная включается только явно через
  `data-theme='dark'` (дебаг-тумблер), привязки к
  `prefers-color-scheme` нет.
- Шрифты — вариант B после теста A–E (переключалка сохранена):
  Philosopher (разделы/лого) + Onest (всё остальное) через Google
  Fonts в `index.html`. Шрифтовые роли — CSS-переменные
  `--font-heading/--font-dish/--font-nav/--font-body/--font-label` в
  `src/index.css`; дефолт зашит в `:root`, варианты — атрибутом
  `[data-fonts]` на `<html>`.
- Корзина (этап 4): стейт — `Map<ключ, кол-во>` в хуке
  `src/hooks/useCart.ts` (ключ позиции — `"<id раздела>:<название>"`),
  без стейт-менеджера.
  Кнопка в хедере справа, drawer справа — `src/components/CartDrawer.tsx`.
  Цены на карточках — кликабельные пилюли-степперы
  (`src/components/PriceStepper.tsx`, `QtyStepper` переиспользуется
  в корзине). «Сформировать заказ» открывает WhatsApp с готовым
  текстом заказа (телефон РФ обязателен: маска `formatPhoneRu` в
  `src/lib/format.ts`). «Сохранить в PDF» генерирует файл и скачивает
  его на ПК (`src/lib/exportPdf.ts`, разметка листа —
  `src/components/CartPdfSheet.tsx`: html2canvas-pro снимает скрытый
  pdf-лист в canvas, jsPDF кладёт в A4; позиции без фото — компактным
  блоком внизу, итог — с разбивкой по разделам).
- Калораж: поле `calories` в типах, в карточках — `≈ N ккал` в нижнем
  левом углу (цена — в противоположном). Цифры — приблизительные
  оценки по составу блюд (на оригинале КБЖУ нет), помечены в
  `src/content/menu.ts`: подтвердить у владельца и заменить реальными.
- Дебаг-инструменты в правом нижнем углу
  (`src/components/ThemeDebugToggle.tsx` +
  `src/components/FontDebugToggle.tsx`): тумблер темы и переключалка
  шрифтовых вариантов A–E. Временные, помечены как debug — убрать
  перед презентацией владельцу, если попросят.
- **Хедер (`src/components/Header.tsx`, `src/styles/01-header.css`)**: полная
  горизонтальная навигация по разделам показывается только от
  `1100px` (переход в бургер — на `@media (max-width: 1099px)`). Это
  не произвольное число: `.header__nav` делит контейнер `1100px` с
  `main`/`.hero__inner`, и `1099px` — нижняя граница, при которой
  текущий набор пунктов (уплотнённый до `gap: 10px`/`font-size:
  14px`) реально помещается без обрезки. При добавлении нового
  раздела меню (нового пункта нава) пересчитать: на `≥1100px`
  `.header__nav.scrollWidth` не должен превышать `.clientWidth` —
  иначе баг с молчаливой обрезкой пунктов (найден в 2026-09,
  см. `docs/CHANGELOG.md`) вернётся. Бургер-кнопка анимированно
  превращается в крестик через абсолютно позиционированные `span`
  (не смена иконки) — при правках сохранять `transition` и
  `prefers-reduced-motion`-гварды. `.header__bar` и `main` нарочно
  используют одинаковый паддинг (`20px`) — иначе бургер/корзина
  визуально не совпадают с правым краем карточек.
- **Порядок каскада в `src/styles/` важен**: App.css — агрегатор
  @import, номера партиалов (01-header … 09-pdf) задают порядок.
  При равной специфичности в CSS побеждает правило, которое стоит в
  файле позже — независимо от того, внутри `@media` оно или нет.
  Нашли на этом баг: компактный мобильный блок
  `@media (max-width: 520px)` стоял раньше безусловных правил тех
  же селекторов и молча игнорировался (рендерились десктопные
  размеры карточек/степпера — `src/styles/06-cards.css`). При
  добавлении нового `@media`-блока с переопределением — ставить его
  *после* всех безусловных правил, которые он должен перебить.
- Краткая история изменений — `docs/CHANGELOG.md`, детали и статус
  этапов — `docs/PLAN.md`.
- Не деплоить никуда и не пушить breaking-изменения без явного
  запроса — на этапе 2-4 всё ещё локальный/демо-проект, финальное
  решение по деплою — за владельцем (этап 5).
