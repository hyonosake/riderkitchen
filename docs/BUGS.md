# Баги и находки на riderkitchen.ru

Собрано при переносе контента на этапе 1 — разбором реального HTML
(WordPress + Astra + Elementor/Elementor Pro), не визуально. Хороший
материал для презентации владельцу: конкретные, проверяемые находки.

## Контент

- **"Готовый сет 5" показывает разный состав в зависимости от блока
  разметки**: в одном месте страницы — "Салат с уткой", в другом
  (дублирующемся блоке, видимо под другой брейкпоинт/слайдер) — "Салат
  с перепелкой". Цена и остальные позиции сета совпадают. То есть
  разным посетителям может показываться разный состав одного и того
  же сета.
- Опечатки в описаниях: квадратные скобки вместо круглых минимум в 3
  местах ("оливковое масло]", "в панировке]", "(горошек]"), двойная
  "й" в "сырныйй мусс" (сэндвич с мортаделлой).
- Разнобой в написании: "авакадо/авокадо", "шиитаки/шиитаке",
  "цурикакэ/фурикакэ" — в разных копиях одного и того же блюда.
- У пункта "Куриная грудка, цукини" в одном из блоков цена указана как
  просто `490` без "р." — несогласованный формат.
- Весь HTML содержит контент меню **продублированным as-is** (похоже,
  отдельные версии под десктоп/мобайл или слайдер) — отсюда и
  расхождения выше: одну и ту же правку нужно вносить в двух местах,
  что и приводит к рассинхрону.

## Изображения

- Фото есть у всех блюд и у всех готовых сетов, кроме категорий
  "Гарниры" и "Напитки" (там фото нет вообще ни у одной позиции) —
  это подтверждено разбором HTML: у каждой карточки блюда фото идёт
  прямо перед названием в разметке.
- **Все `alt`-атрибуты у изображений пустые** (`alt=""`) — плохо для
  SEO и доступности (скринридеры).
- Часть фото (примерно половина) загружена под техническими именами
  из фоторедакторов — `MagicEraser_...png`, `Bazaart_...png`,
  `IMG_XXXX.png` — без привязки к названию блюда в самом имени файла.
  Более старые фото (2023 год) названы по блюду человеко-читаемо,
  а более новые (добавлены с мая 2025 по июнь 2026) — нет. Похоже,
  на каком-то этапе перестали переименовывать файлы при загрузке —
  стоит либо продолжить называть по блюду, либо это не принципиально
  (для сайта не важно, только для порядка в медиатеке).
- Фото для блюда "Рыба в кляре, рис жасминовый" называется
  `Это-фото-уже-есть-не-обрабатываем-смотрим-коммент-1.png` — рабочая
  пометка редактора ("это фото уже есть, не обрабатываем, смотрим
  комментарий"), случайно попавшая в название файла, который сейчас
  реально показывается посетителям сайта (то есть виден в прямой
  ссылке на изображение).
- Фото для блюда "Салат с уткой" называется `Салат-с-перепелкой-2-1.png`
  ("салат с перепёлкой") — похоже, блюдо когда-то переименовали
  (с перепёлки на утку), а файл фото остался под старым именем.
  Не влияет на то, что видит посетитель, но заметно в адресе картинки.
- Фото не оптимизированы на оригинале: PNG в высоком разрешении, часть
  файлов — по 2560px на широкую сторону и весом до 5-8 МБ каждый
  (суммарно по сайту фото блюд — уже под сотню МБ). Нет WebP/AVIF, нет
  отдельных размеров под мобильный экран. Это ощутимо на скорости
  загрузки, особенно на мобильном интернете.
  **В нашей версии починено**: все фото сконвертированы в WebP
  (`cwebp`, q82, ресайз до 900px по короткой стороне) —
  `src/assets/` с ~85 МБ до ~6 МБ.

## Технически

- Сайт на WordPress + Elementor/Elementor Pro + Astra + Unlimited
  Elements — это объясняет тяжёлый HTML (~430 КБ) с глубокой
  вложенностью и дублирующимися блоками контента под разные
  брейкпоинты вместо адаптивной вёрстки на CSS.
- Навигация — только якорные ссылки на секции одной страницы (нет
  отдельных URL для разделов меню, что ограничивает SEO по отдельным
  категориям).
