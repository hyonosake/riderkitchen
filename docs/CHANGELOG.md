# Changelog

Хронология доработок локальной версии Rider Kitchen (по сравнению с
этапом 1 — первичный перенос контента). Детали и мотивация — в
[`docs/PLAN.md`](PLAN.md), находки по оригиналу — в [`docs/BUGS.md`](BUGS.md).

## CI и публикация

- Настроен GitHub Actions CI (`.github/workflows/ci.yml`): на push в
  `main` и на pull request гоняются четыре независимые (параллельные)
  джобы — lint, unit, e2e, build — чтобы провал линта не маскировал
  провал тестов. e2e-джоба ставит chromium (`npx playwright install
  --with-deps chromium`), отчёт Playwright сохраняется артефактом на
  7 дней при провале.
- Вся накопленная работа — тестовая инфраструктура и рефакторинг
  R0–R6 (записи ниже, схема — [`docs/REFACTOR_PLAN.md`](REFACTOR_PLAN.md)) —
  закоммичена и запушена в `main`. Итоговые прогоны перед пушем:
  unit 67 passed, e2e 26 passed (4 вьюпорта), lint 0/0, build зелёный.

## Hero и заголовки

- Hero перевёрстан из фоновой картинки с `object-fit: cover` в
  двухпанельную композицию: слева kicker-бейдж + H1 (`text-wrap: balance`)
  + подзаголовок + две CTA-кнопки (телефон из `contacts`, якорь на сеты),
  справа постер-логотип на натуральной пропорции 1680×994. Баг с
  обрезкой постера и налезающим текстом хедера закрыт.
- Бейдж «N готовых сетов · от X ₽» считается из контента, не зашит.
- Тексты Hero вынесены в `src/content/hero.ts`.
- Шапки разделов: паттерн «01 — Заголовок — счётчик позиций»,
  `clamp()`-типографика, русские формы числительных (`pluralizeRu`).
- Инфраструктура: `scroll-behavior: smooth` + `scroll-padding-top`
  под sticky-хедер, `prefers-reduced-motion`, глобальный `:focus-visible`,
  стили кнопок `.button--primary/--ghost`.

## Шрифты и тема

- Шрифтовые роли (`--font-heading/dish/nav/body/label/price`) +
  переключалка вариантов A–E (`FontDebugToggle`, атрибут `data-fonts`,
  localStorage, раннее применение до монтирования React).
- По итогам теста выбран вариант B и зашит дефолтом: Philosopher
  (разделы/лого) + Onest (всё остальное). Переключалка сохранена.
- Тема по умолчанию — светлая; тёмная — только явно через
  `data-theme='dark'` (дебаг-тумблер), привязки к
  `prefers-color-scheme` нет.
- Новый акцентный цвет: травяной зелёный `#3a7d44` (тёмная тема —
  мятный `#8ccfa0`) вместо терракотового.
- `lining-nums` на цифрах (цены, метки, телефон) — у Alegreya-вариантов
  старостильные цифры выровнены.

## Карточки и цены

- Цена перенесена в нижний правый угол карточки (`margin-top: auto`
  прижимает футер к низу при разной высоте описаний).
- Цена — интерактивная пилюля (`PriceStepper`): ховер — заливка
  акцентом, клик — степпер «− цена за единицу +», количество — `× N`
  сбоку. Ноль возвращает кнопку в состояние цены.
- Калораж `≈ N ккал` в нижнем левом углу карточки (цена — в
  противоположном). Цифры — приблизительные оценки по составу блюд:
  на оригинале КБЖУ нет, подтвердить у владельца (помечено в
  `src/content/menu.ts`).

## Корзина

- Стейт — `Map<ключ, кол-во>` в `App.tsx` (ключ `"<id раздела>:<название>"`),
  без стейт-менеджера; степперы на карточках контролируемые, синхронны
  с корзиной.
- Кнопка корзины в хедере справа: иконка + живая сумма + бейдж
  количества.
- Drawer справа: список позиций с суммами и компактными степперами,
  «Очистить корзину», итог.
- Телефон РФ с маской (`formatPhoneRu`: 8…/9… → `+7 (…) …-…-…`).
- «Сформировать заказ» — WhatsApp с готовым текстом заказа; кнопка
  неактивна, пока телефон неполный.
- «Сохранить в PDF» — генерация и скачивание файла
  (`jspdf` + `html2canvas-pro`, динамический `import()` в отдельных
  чанках): A4, постраничная нарезка длинных заказов, светлая палитра
  независимо от темы.

## PDF-выгрузка заказа

- Раскладка строки: фото | название + описание | × кол-во (+калораж
  позиции) | стоимость.
- Позиции без фото (гарниры, напитки) — компактными строками отдельным
  блоком в самом низу списка.
- Итог: разбивка количества по разделам («Закуски — 2 · Супы — 1 …»),
  суммарный калораж, итоговая цена крупным акцентом.

## Мобильный аудит: сжатые карточки и степпер за краем карточки

- Найдена причина «chunky»-вида на мобильных: медиа-блок
  `@media (max-width: 520px)` в `src/App.css` стоял в файле раньше
  безусловных правил для тех же селекторов (`.price-pill`,
  `.price-pill--active`, `.price-pill__step`, `.dish-card__body` и
  т.д.) — при равной специфичности в каскаде побеждает более позднее
  правило, поэтому компактные мобильные размеры молча игнорировались
  и рендерились десктопные. Блок перемещён после соответствующих
  правил.
- `.dish-card__footer` — `flex-wrap: wrap`: если активный степпер
  (−/+) не помещается рядом с калоражем в узкой 2-колоночной
  карточке, переносится на свою строку вместо наезда на текст/край
  карточки. `.price-stepper` — `margin-left: auto`, чтобы степпер
  прижимался вправо и на перенесённой строке.
- Добавлен ещё один компактный уровень `@media (max-width: 360px)`
  (по аналогии с уже существующим для хедера) — на самых узких
  экранах степпер оставался шире карточки даже на своей строке.
- Проверено: `npm run lint`, `npm run build`, полный
  `npx playwright test` — 26 passed на всех 4 вьюпортах.

## Браузерный UI-аудит: хедер, бургер-анимация, выравнивание

- Нашли реальный баг в горизонтальной навигации на десктопе/планшете:
  `.header__nav` с `overflow-x: auto` молча обрезал пункты без
  какого-либо визуального намёка на скролл — на 1440px последний
  пункт «Напитки» показывался как «На», на 768px было видно только 2
  из 9 пунктов. Причина — общий с `main`/`.hero__inner` контейнер
  `max-width: 1100px` не оставлял навигации достаточно места ни при
  одной ширине окна (замерено `scrollWidth`/`clientWidth` — оверфлоу
  был на любой ширине). Точка перехода в бургер-меню поднята с
  `720px` до `1099px` (полная навигация — только там, где реально
  помещается, `≥1100px`), сама навигация уплотнена (`gap: 24px →
  10px`, `font-size: 16px → 14px`). После фикса — 0px оверфлоу на
  1100/1280/1440/1920.
- Бургер-кнопка: три линии абсолютно позиционированы внутри кнопки и
  плавно превращаются в крестик при открытии (верхняя/нижняя
  поворачиваются на ±45° и сходятся к центру, средняя растворяется) —
  `transition` 0.25s, с уважением `prefers-reduced-motion`.
  `src/App.css`, `src/components/Header.tsx`.
- Хедер на мобильных выглядел «слишком по центру»: `.header__bar` не
  задавал `justify-content`, а `nav` (обычно `flex: 1`-распорка,
  прижимающая корзину/бургер к правому краю) на мобильных скрыт —
  логотип, корзина и бургер просто липли к левому краю. Плюс
  горизонтальный паддинг хедера (`28px`) не совпадал с паддингом
  `main` (`20px`). Добавлен `justify-content: space-between`,
  паддинг унифицирован до `20px` — бургер теперь пиксель-в-пиксель
  совпадает с правым краем карточек на всех ширинах.
- Крестик закрытия в drawer корзины (`.cart-drawer__close`) не был
  центрирован: кнопка не была флекс-контейнером, а символ «×» сам по
  себе смещён по вертикали в большинстве шрифтов. Заменён на inline
  SVG-крестик (тот же паттерн, что иконка корзины в хедере) с явным
  `display: flex; align-items/justify-content: center`.
  `src/components/CartDrawer.tsx`, `src/App.css`.
- CTA-кнопка с телефоном в Hero переносилась посередине номера на
  любой ширине ≤880px (там, где Hero уже одноколоночный): кнопки
  делили строку поровну (`flex: 1`), и доли не хватало под
  «+7 (926) 910 10 10». На ≤880px кнопки теперь в столбик на всю
  ширину вместо равного деления строки; десктоп (>880px, кнопки в
  ряд) не затронут.
- Аудит и все фиксы проверены Playwright-скриншотами на 320/375/414/
  560/600/768/900/1024/1100/1280/1440/1920px (временные тестовые
  файлы, в репозитории не остались) + полным прогоном `npx playwright
  test` (26 passed), `npm run lint`, `npm run build` после каждого
  изменения.

## Рефакторинг: разбиение App.css на партиалы (R3)

- `src/App.css` (1234 строки) разбит на 9 партиалов в `src/styles/`
  с нумерацией по порядку подключения: `01-header.css` (хедер,
  бургер, media 720/1099/360), `02-debug.css` (дебаг-панель),
  `03-hero.css` (hero, media 880), `04-buttons.css` (кнопки),
  `05-menu.css` (main, разделы меню, media 1800), `06-cards.css`
  (карточки/пилюли-степперы, media 520/360), `07-footer.css`
  (футер), `08-cart.css` (корзина: overlay + drawer),
  `09-pdf.css` (PDF-лист).
- Гарантия порядка каскада: `src/App.css` стал агрегатором —
  только `@import` партиалов в прежнем порядке блоков исходника
  плюс комментарий-предупреждение. Vite инлайнит `@import`
  (postcss-import) с сохранением порядка, поэтому позиция каждого
  `@media`-блока относительно своих базовых правил не изменилась
  (критичный кейс — media 520/360 после безусловных `.price-pill*`,
  тот самый баг из AGENTS.md). Партиалы вырезаны подряд, без
  перестановок и правок правил.
- Сверка байт-в-байт: CSS-бандл `dist/assets/index-*.css` после
  разбиения совпал с эталоном R0 (18522 байта,
  sha256 `a7f15a40…3fc`) — ноль визуальных и каскадных отличий.
- `src/index.css` (токены/шрифты) не тронут. Схема и мотивация —
  `docs/REFACTOR_PLAN.md` (этап R3). Прогоны после шага: unit 49
  passed, e2e 26 passed (4 вьюпорта), lint 0/0, build зелёный.
