# Rider Kitchen — план работ

Цель: сделать локальную версию сайта кейтеринг-сервиса, поправить баги,
аккуратно разбить на компоненты, добавить новые фичи — и презентовать
результат владельцу.

Стек: **React + TypeScript + Vite**. Линтер — oxlint (уже настроен,
быстрый, без лишнего конфига). Без state-менеджеров, роутеров и т.п.,
пока не понадобится — сайт в основном контентный.

Статус: этап 1 в основном сделан — меню перенесено, сайт открывается
локально. Сайт оригинала — WordPress + Elementor
(riderkitchen.ru), доступа к исходникам/хостингу нет, поэтому контент
выгружен разбором публичного HTML, а не 1:1 копией файлов.

## Как запускать

```bash
npm install      # один раз
npm run dev      # локальный сервер с hot-reload
npm run build    # прод-сборка в dist/ (проверяет типы + собирает)
npm run preview  # локально посмотреть прод-сборку
npm run lint      # быстрый линт (oxlint)
```

## Этап 3 — разбивка на компоненты

Цель — не "разбить ради разбивки", а получить структуру, в которой
легко добавлять фичи из этапа 4.

Черновая структура:

```
src/
  components/     # переиспользуемые UI-блоки (Header, Footer, Button, Card...)
  pages/          # секции/страницы сайта (Home, Menu, Contacts...)
  content/        # тексты, меню, цены — отдельно от разметки
  assets/         # изображения, иконки
```

Принципы:

- Компонент — если кусок используется 2+ раза или является явной
  смысловой единицей (карточка блюда, форма заявки, хедер).
  Не выносить в компонент то, что используется один раз и не несёт
  самостоятельного смысла — это лишний слой абстракции.
- Контент (тексты/цены) отдельно от компонентов — проще редактировать
  и презентовать владельцу изменения без переписывания JSX.
- Строгая типизация: описать типы для меню/блюд/цен и т.п. — раз уж
  нравится строгая типизация, это то место, где она даёт больше всего
  пользы (опечатка в поле сразу подсвечивается).
